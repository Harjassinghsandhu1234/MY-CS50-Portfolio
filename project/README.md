# IS THE NUMBER DISARIUM?
#### Video Demo:  <https://youtu.be/NSW3MRTtqOc>
#### Description:
"Is the Number Disarium?" is a small C program I built for my CS50 final project. It does one simple job: it asks the user to type in a number, and then tells them whether that number is something called a "Disarium number." If you've never heard of a Disarium number before, don't worry, neither had I until I went looking for project ideas. It's a fun, slightly obscure bit of math trivia, and it turned out to be a good fit for a beginner C project since it touches on loops, arrays, and a bit of custom math, without being overwhelming.

So what exactly is a Disarium number? A number is called a Disarium number if you take each of its digits, raise it to the power of its position in the number (counting from the left, starting at 1), and then add all of those results together. If the total you get equals the original number, you've found a Disarium number. An example always makes this clearer. Take the number 135. The first digit is 1, in position 1, so 1^1 = 1. The second digit is 3, in position 2, so 3^2 = 9. The third digit is 5, in position 3, so 5^3 = 125. Add those together: 1 + 9 + 125 = 135, which is exactly the number we started with. So 135 is a Disarium number. Not every number works out this neatly, and that's part of what makes checking for them interesting in the first place.

When you run the program, it uses CS50's own library to ask the user for a number (the get_long function does the heavy lifting here, and it keeps re-asking if the input isn't a valid positive whole number). Once it has a number, the program needs two things before doing any math: how many digits the number has, and what each digit is, in order from left to right.

To count the digits, the program just keeps dividing the number by 10 in a loop until nothing is left, counting each division as it goes. Once it knows the digit count, it goes through the number a second time, this time pulling out each digit one by one and storing it in an array, starting from the most significant digit down to the least significant one. This part took me a while to get right, because digits naturally come out in reverse order when you use modulus (%) and division together, so I had to think carefully about how to place each one so the order matches its real position in the number.

Once the digits are stored, the program loops through the array and raises each digit to the power of its position, using a small helper function I wrote myself called power, instead of calling the math library. I did it this way mainly because I wanted to actually understand how exponentiation works step by step, rather than treating it like a black box. Each result gets added to a running total as the loop goes. When the loop finishes, the program compares that total to the original number. If they match, it prints a message saying the number is a Disarium number, and if they don't match, it lets the user know it isn't. That's pretty much the whole program in a nutshell.

The project has one main file, disarium.c, plus a separate file, test_disarium.c, with a small set of tests in the style CS50 uses for testing helper functions. These check that the digit-counting, digit-extracting, and power functions all behave correctly on a handful of known cases, including tricky edge cases like single-digit numbers and zero.

If I'm honest, the hardest part of this project wasn't really the math, it was getting comfortable with arrays again after working mostly with Python in earlier problem sets. Things that barely cross your mind in Python, like deciding an array's size ahead of time or worrying about off-by-one mistakes, took real trial and error in C. I also lost a good chunk of an evening to a bug where I was filling the digit array in the wrong direction, which gave completely wrong answers for any number with more than one digit, even though the logic looked fine at first glance.

If you'd like to try it out, just compile it with make disarium, then run ./disarium and type in any positive whole number when it asks. A few good ones to test are 1, 89, 135, and 175, all of which are Disarium numbers, along with any random number you like, just to watch it correctly say no.
